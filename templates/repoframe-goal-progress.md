# 目标进展路径

目标 JSON 的 `progress` 保存执行计划和真实结果。仅查看目标不修改路径；实际执行目标必须处于 default 模式。未开始时为 `{"current":null,"nodes":[]}`。

```json
{
  "current": 1,
  "nodes": [
    { "id": 0, "kind": "start", "title": "开始目标", "previous": [], "status": "done", "message": "已确认目标范围并建立执行计划。" },
    { "id": 1, "title": "完成核心实现", "previous": [0], "status": "active", "message": "" },
    { "id": 2, "title": "验证主要流程", "previous": [1], "status": "planned", "message": "" },
    { "id": 3, "kind": "end", "title": "目标完成", "previous": [2], "status": "planned", "message": "" }
  ]
}
```

- `id` 和 `previous` 中的引用均为非负安全整数；首次从 0 开始，新增使用最大 ID 加一，不重新编号。顺序由前序关系决定，不能有重复 ID、无效引用或环。
- `title` 是计划阶段或预期结果，完成后保留；`message` 只在完成后写一至两句实际结果及关键验证，支持 Markdown。`done` 必须有消息，`planned/active/abandoned` 的消息必须为空，不记录执行播报。
- `current` 指向主 Agent 当前关注且未放弃的节点；并行可以有多个 `active`。非空路径有且仅有一个开始、一个结束，开始没有前序，所有节点可从开始到达。

## 维护

1. 首次实际执行时先规划完整的“开始 → 关键阶段 → 结束”，通常 3–6 个工作阶段。已有路径则读取并继续，不重复建图，不为每次命令、工具调用或小修改建节点。
2. 正常推进更新已有节点；细节变化调整未执行计划。实质转向才分叉：保留已发生记录，将不再执行的计划标为 abandoned，并先规划新路如何完成或汇入既有路径，不能只写孤立的下一步。必要的决策可独立成节点，完成消息记录选择和原因。
3. 实际并行才分叉，预先明确各分支和汇合位置；汇合节点引用各分支末端，前序完成后再推进。替代路线不添加为必须同时完成的依赖。保留执行的计划必须通向结束；已放弃的历史分支允许终止。
4. 主 Agent 统一写目标文件，子 Agent 回报结果，不并发写同一文件。本规范不授权或要求创建子 Agent。保存前重读文件，保留其他字段；外部修改冲突时重新核对，不覆盖新内容。
5. 暂停或受阻保留位置，不填完成消息；原因在当前对话报告，只有导致实质计划变化时才调整路径。恢复时核对真实状态。全部完成条件经验证后，整理分支、完成结束节点并填写真实消息，再将目标设为 completed 并清除对应 Active Goal。
6. 用户可以手动完成目标而保留未完成节点，不补造缺失结果。已完成目标重新启用且需要追加工作时，保留旧节点和消息，将原结束节点转为普通历史节点，再添加阶段和新结束节点，旧 ID 不变。

旧进展由 init 一次性迁移；“导入历史进展”节点消息保留原文，仅表示导入完成，不代表重新验证了历史工作。迁移后的路径由 Agent 在恢复目标时核对并补充实际计划。
