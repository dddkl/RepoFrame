# PROJECT.md

This file defines the project itself. It contains durable facts, not daily execution notes.

It may be used in either of these ways:

- as the primary structured project definition generated by the agent
- as a compatibility layer that preserves a user-authored project plan and adds a small agent-readable snapshot

## Initialization Input Schema

When initializing from a single prompt, the agent should extract the following fields:

- `name`: project name
- `type`: project type
- `goal`: primary project goal
- `users`: target users
- `use_cases`: core use cases
- `stack`: preferred technology stack
- `stage`: current stage
- `constraints`: known limits or requirements
- `non_goals`: explicit exclusions

If a field is missing, the agent should infer a reasonable default and record the inference under `Assumptions`.

## Compatibility Rule

If the user provides an existing project plan in any format, the agent should preserve that source material by default.

In that case, `PROJECT.md` should act as an agent-readable entry point that:

- records the source mode
- points to the original source file
- stores a concise snapshot of key fields
- avoids rewriting the original plan unless the user explicitly requests it
